3. Năm đặc tính NIST

  1. On-demand self-service: Sinh viên tự tạo Codespace trên GitHub mà không cần người quản trị cấp máy.
  2. Broad network access: API có thể truy cập qua HTTPS từ trình duyệt trên điện thoại.
  3. Resource pooling: Codespace sử dụng hạ tầng điện toán được nhà cung cấp quản lý và chia sẻ.
  4. Rapid elasticity: GitHub cho phép thay đổi loại máy Codespace khi cần thêm tài nguyên. Chưa thực nghiệm thay đổi loại máy.
  5. Measured service: GitHub theo dõi mức sử dụng tính toán bằng core-giờ và lưu trữ bằng GB-tháng.

4. Kết luận

III. CÂU HỎI PHẢN BIỆN

Câu 1. Tại sao notes2 vẫn báo RAM máy chủ?

API sử dụng hàm đọc thông tin bộ nhớ hệ thống nên có thể trả về RAM của máy chủ thay vì giới hạn cgroups. Docker sử dụng cgroups để giới hạn container ở 128 MiB. Ứng dụng Node.js hoặc Java cần nhận biết giới hạn bộ nhớ thực tế để tránh lỗi OOM và cấu hình heap phù hợp.

Câu 2. Time-shared và Space-shared khác nhau thế nào?

Time-shared chia sẻ thời gian CPU giữa các Cloudlet. Space-shared cấp phát lõi CPU cho các Cloudlet đủ điều kiện, tác vụ còn lại phải chờ khi thiếu tài nguyên. Nhà cung cấp gói giá rẻ có thể ưu tiên Time-shared để tăng mức sử dụng CPU và giảm chi phí, đồng thời cần kiểm soát tình trạng tranh chấp tài nguyên.

Câu 3. Lợi ích và hạn chế của mô phỏng?

CloudSim Plus hỗ trợ đánh giá hiệu suất, thử nghiệm lập lịch, dự đoán mức sử dụng tài nguyên và lựa chọn cấu hình trước khi thuê hạ tầng thực tế. Tuy nhiên, kết quả có thể sai lệch do độ trễ mạng, truy cập ổ đĩa, tải biến động, chi phí ảo hóa và các sự cố phần cứng chưa được mô phỏng đầy đủ.
